# Music Manager v2.0.0

*November 2026. Covers everything since v0.2 (19 Sep 2026): PRs #52, #54, #55, #56, #57 and #58.*

The main changes:

- **One library for every source.** YouTube, SoundCloud and custom
  playlists now work the same way, and YouTube has a Liked Songs playlist.
- **A rebuilt desktop app** on Tauri v2. It ships as a single file and starts
  with no setup.
- **Security fixes** for everything an automated review found.
- **A YouTube matching engine**, groundwork for Spotify later.

---

## What's new

### Library and search, the same for every source
- **One Library screen** with a source switch: Custom Playlists, YouTube,
  SoundCloud. Each source shows its playlists the same way and has one
  "Connect / Reconnect" panel when it needs a login.
- **YouTube Liked Songs** appears as a playlist, pinned first. It shows liked
  videos from the Music category only.
- **Like and unlike** from the app. The first time you like a video, YouTube
  asks for one extra permission; read-only users keep the smaller consent
  until then.
- **"Load more"** paging for long playlists and search results.
- **Search** has the same source switch. SoundCloud searches public tracks
  without a login.

### Desktop app
- **Login opens in your normal browser.** "Connect YouTube" / "Connect
  SoundCloud" opens the consent page in your default browser, where you're
  usually already signed in. Afterwards the browser hands you back to the
  app (`musicmanager://`); your browser will ask before opening it.
- **Starts with no configuration.** The app creates its own secrets on first
  run.
- **Your data lives in your user folder:**
  - macOS: `~/Library/Application Support/Music Manager/`
  - Windows: `%APPDATA%\Music Manager\`
- **Ships with ffmpeg and yt-dlp.** If they're missing, it falls back to
  Homebrew or other system installs.
- Tray menu, hide-on-close and background playback work as before. On
  macOS, clicking the Dock icon brings a hidden window back.

### Playback and everyday use
- **You stay connected:** YouTube sessions renew automatically instead of
  logging you out after about an hour. You're only asked to reconnect if
  renewing fails.
- **Clear messages instead of silent failures.** Connection problems,
  expired sessions and unplayable tracks show a short notice.
- **Unplayable tracks are skipped** instead of stopping the queue.
- **The audio cache is capped at 500 MB** (`CACHE_MAX_BYTES`), dropping
  the least recently played tracks first.
- **`GET /api/health`** reports the app, yt-dlp and ffmpeg versions and
  cache usage, which helps when "nothing plays".

### Matching engine (groundwork, not visible yet)
A YouTube match engine (`services/matcher/`) finds the official YouTube
version of a track by title, artist, duration and ISRC, with manual
override and "wrong match" reports. It's built and tested but not used by
any screen yet. It's the basis for Spotify (Free) playback, which is on hold.

## Security

An automated security review (Exploiter and Clogger agents, 8 Nov) found
these issues. All are fixed, and the re-scan on 9 Nov confirmed it.

- **High:** a crafted SoundCloud search cursor could make the server fetch
  any address and send the SoundCloud login token there.
- **High:** production dependency advisories (one critical). Production
  dependencies now show 0 advisories, and CI blocks new high-severity ones.
- **Medium:** one user could change the title or thumbnail other users see
  for a shared track. Display data is now stored per user, and only
  `https` thumbnails are accepted.
- **Medium:** yt-dlp and ffmpeg processes could pile up after a listener
  left. They now have time limits and are stopped on disconnect.
- **Medium:** the desktop app had no content security policy and broad
  shell permissions. It now has a strict policy and no shell access from the
  web page.
- **Low:** log injection through an OAuth error parameter; login tokens
  without an expiry were accepted.

These hardening changes came from the work itself rather than the review:
- **Encrypted tokens:** stored Google and SoundCloud tokens are encrypted
  (AES-256-GCM). Existing tokens are converted on first start.
- **Login tokens can't be swapped:** the temporary token used during
  sign-in can no longer work as a full login.
- **Local-only server:** it only listens on this computer (127.0.0.1); set
  `HOST` to change that.

One finding is still open (tracked as an issue): **`/stream` needs a signed,
short-lived link.** At the moment another web page can make the running
server start a transcode, though at most 2 continue after a disconnect.

## Under the hood
- **Single-file server:** the server is a Node single executable, replacing
  the abandoned `pkg`, which was stuck on Node 18.
- **Built-in database:** the database uses Node's built-in `node:sqlite`. The
  native `sqlite3` addon is gone, and existing `database.sqlite` files open
  as-is.
- **Smaller Google library:** `googleapis` is replaced by `@googleapis/youtube`,
  which shrinks the server code from 32 MB to 2.5 MB.
- **Tauri v2:** the desktop shell moves from Tauri v1 to v2, which also
  clears five Rust dependency alerts.
- **CI:**
  - Tests, a build of the single executable and a no-config boot test run on
    Linux, macOS and Windows.
  - A desktop compile and lint check runs on every PR.
  - The release workflow builds macOS and Windows server executables.
- **Tests:** 569 automated tests, up from 105 at v0.2.

## Breaking changes and upgrade notes
- **Node.js 22.13 or newer is required** (for `node:sqlite`). Node 20 won't
  start the server.
- **After upgrading, run `npm ci`** in the project and in `client/`.
  Several packages were added or removed.
- **API error codes are unified.** `GOOGLE_NOT_CONNECTED`,
  `SOUNDCLOUD_TOKEN_EXPIRED` and similar are replaced by
  `SOURCE_NOT_CONNECTED`, `SOURCE_TOKEN_EXPIRED`, `TRACK_UNAVAILABLE` and
  `SOURCE_TIER_REQUIRED`, always with a `source` field.
- **The old `/search`, `/playlists` and `/api/soundcloud/*` routes still
  work**, but they're deprecated in favour of `/api/library/:source/...` and
  `/api/search/:source`, and will be removed in a later release.
- **Packaged app data has moved** to your user folder (see above). In
  development (`node server.js`), everything stays in the project folder as
  before.
- **Configuring the packaged app:** put `GOOGLE_CLIENT_ID` /
  `GOOGLE_CLIENT_SECRET` (and optionally SoundCloud credentials) in a `.env`
  file in that data folder.
- **New optional settings** (see `.env.example`): `HOST`,
  `TOKEN_ENCRYPTION_KEY`, `CACHE_MAX_BYTES`, `MUSIC_DATA_DIR`, `FFMPEG_PATH`,
  `YTDLP_PATH` and the `MATCH_*` engine settings.
- **Your Google redirect URI doesn't change:**
  `http://localhost:3000/auth/google/callback`.

## Known limitations
- **Custom playlists can't be created from the app yet.** The "Create
  Playlist" card isn't connected to anything, and there's no "Add to
  playlist" button. Existing custom playlists display and play normally.
- **The executables aren't signed.** macOS Gatekeeper and Windows
  SmartScreen will warn. On macOS, right-click → Open the first time.
- **No installer is published yet.** The release workflow attaches the
  *server* executables (plus ffmpeg and yt-dlp) for macOS and Windows, not
  the full app (`.dmg` / `.msi`). Build the app yourself with
  `npm run tauri:build`.
- **On macOS, `musicmanager://` links only work from the built app**, not
  from `npx tauri dev`.
- **SoundCloud libraries need API credentials**, which SoundCloud only
  issues to Artist Pro accounts. Without them, SoundCloud search and
  playback still work through yt-dlp.
- **Spotify, Apple Music and Tidal are on hold** until a paid subscription
  is available; see `ROADMAP.md`. In-app DRM playback isn't planned.
- **One Linux-only Rust alert remains** (`glib`); it needs a newer GTK stack
  than Tauri supports today.
- **Playback against real YouTube and SoundCloud** is tested by hand only;
  CI has no network accounts.

## How to test this release

**Set up**
1. Check `node -v`: 22.13 or newer.
2. Run `npm ci && (cd client && npm ci)`.
3. Put yt-dlp in `bin/` (`yt-dlp_macos` / `yt-dlp.exe`), or install it
   with `brew install yt-dlp`.
4. Run `npm test`. Expect 569 passing.

**Web version** (`npm run dev`, then open http://localhost:5173)
1. Register a new account, log out, and log in again.
2. Connect YouTube. You should see the "YouTube connected." notice, and the
   connect banner should disappear.
3. Library → YouTube: your playlists should appear, with **Liked Songs**
   first. Open one and use **Load more** if it's long.
4. Search YouTube, then play a track. Check that seek, next/previous and
   the queue work.
5. Like a track. The first time, you should be asked for the extra
   permission; after that the like should go through.
6. SoundCloud search: play a track. Preview-only tracks are marked.
7. Leave the app for over an hour, then play something. It should keep
   working with no reconnect (YouTube session renewal).
8. Recently Played should list what you played.

**Desktop app** (`npm run tauri:build`, then open the built app)
1. First launch: the app should start without any configuration. Check
   that the data folder was created.
2. Connect YouTube: the login should open in your **browser**, and after
   consent the browser should offer to open Music Manager. The app should
   come to the front with the "connected" notice.
3. Close the window: playback should continue, and the tray icon should
   bring the window back. Quit from the tray, and check that no
   `music-server` process is left running.
4. Play a track with the internet off and on, to check the error notice and
   that the queue skips to the next track.

**Things worth a look**
- `GET /api/health` (logged in) should report yt-dlp and ffmpeg versions
  and `status: ok`.
- In an existing database, stored tokens should start with `enc:v1:`.
