# Music Manager v2.0.1

*November 2026. Covers everything since v2.0.0: PRs #60, #61, #62, #63 and #64.*

The main changes:

- **Installers.** The release now includes an installable desktop app for
  macOS and Windows, with everything it needs inside.
- **Custom playlists work from the app:** create them, and add tracks from
  any list.
- **The last open security finding is closed.** Stream links now need a
  signed token.
- **Fixes** for YouTube playback, the SoundCloud search tab, and YouTube
  showing as disconnected after an hour.

---

## What's new

### Installable desktop app
- **macOS (Apple Silicon):** `Music Manager_2.0.1_aarch64.dmg`
- **Windows (x64):** `Music Manager_2.0.1_x64-setup.exe` (no admin rights
  needed) or the `.msi`
- The server, ffmpeg and yt-dlp are inside the app. You don't need Node,
  npm or Homebrew to run it.
- On first launch the app creates a settings file, `.env`, in its data
  folder. Put your own `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` there
  and restart the app. Credentials are never built into the download.
  - macOS: `~/Library/Application Support/Music Manager/.env`
  - Windows: `%APPDATA%\Music Manager\.env`
- Until those are set, the app runs but doesn't offer "Connect YouTube",
  instead of sending you to a broken Google page.

### Custom playlists
- **Create Playlist** in the Library opens a small form and creates the
  playlist.
- **"+ Playlist"** on track rows (Search, and YouTube / SoundCloud
  playlists) adds the track to one of your playlists, or creates a new one in
  the same step.
- Adding a track that is already in the playlist says so and doesn't add
  it twice.

## Fixes
- **YouTube playback.** The server now asks yt-dlp for the audio stream
  explicitly. Before, yt-dlp could answer with two addresses (video and
  audio), and playback failed.
- **Useful errors when a track won't play.** The server log now shows
  yt-dlp's own message (for example a bot check, or an unavailable video), a
  timeout, or how to install yt-dlp if it's missing. At startup it prints
  which yt-dlp and ffmpeg it uses.
- **SoundCloud search without an account.** The SoundCloud tab in Search was
  greyed out when the server had no SoundCloud credentials, although
  searching doesn't need them.
- **YouTube stays connected.** An hour after connecting, the app showed
  YouTube as disconnected (the connect banner came back and the Library tab
  greyed out) although the session was still being renewed.
- **No console windows on Windows** when the app runs yt-dlp or ffmpeg.

## Security
- **Stream links need a signed token** (issue #53, the last open finding
  from the 8–9 Nov review). `/stream` and `/duration` used to accept any
  request that could reach the server, so a web page open in your browser
  could make it start transcodes. The player now gets a short-lived media
  token after login and adds it to every stream link; requests without it
  are refused before any work starts.
- The media token only plays audio. It can't be used to log in, and a login
  token isn't accepted in its place.
- **At most 6 transcodes run at once.** Beyond that the server answers
  "busy".

---

## Upgrade notes
- **`/stream` and `/duration` now require `t=<media token>`**, from
  `GET /api/media/token` (login required, valid 6 hours). The app's own
  player handles this. Anything else that calls these routes directly needs
  the token.
- **Running from source:** run `npm ci` in the project and in `client/`
  after pulling. Node 22.13 or newer is still required.
- No database changes. Existing data and connections carry over.

## Known limitations
- **The installers aren't signed with a paid certificate**, so the system
  warns once:
  - macOS: drag the app to Applications, then allow it under System
    Settings → Privacy & Security → "Open Anyway", or run
    `xattr -cr "/Applications/Music Manager.app"`.
  - Windows: SmartScreen → More info → Run anyway.
- **Nobody has installed and run the installers yet.** They build on
  GitHub and contain the right files, but this release is the first real
  test.
- **YouTube playback is not confirmed.** The fix above addresses one known
  cause. Recent yt-dlp versions may also need a JavaScript helper (`deno`)
  for YouTube, which the app doesn't bundle. If tracks still don't play, the
  server log now says why.
- **You can't remove a track from a custom playlist or delete a playlist**
  from the app yet.
- **Keep the macOS app in `/Applications`:** the login hand-back
  (`musicmanager://`) only reaches an installed app.
- **The app uses port 3000.** Quit a development server (`npm run dev`)
  before starting it.
- SoundCloud libraries still need API credentials; Spotify, Apple Music
  and Tidal are still on hold (see `ROADMAP.md`).

## How to test this release

**Install**
1. Download the `.dmg` (Mac) or `setup.exe` (Windows) from the release and
   install it. Allow it once, as described above.
2. Start Music Manager, then quit it from the tray icon.
3. Open the `.env` file in the data folder, fill in `GOOGLE_CLIENT_ID` and
   `GOOGLE_CLIENT_SECRET`, save, and start the app again.

**Check**
1. Register an account. Click "Connect YouTube": the login should open in
   your browser, and the browser should offer to return to Music Manager.
2. Search YouTube and play a track. Check seeking, next/previous and the
   queue.
3. Search SoundCloud without connecting it, and play a track.
4. Library → Create Playlist. Then use "+ Playlist" on a search result,
   open the playlist and play it.
5. Leave the app open for over an hour: YouTube should still show as
   connected, and playback should still work.
6. Close the window: playback should continue, and the tray icon should
   bring the window back. Quit from the tray and check that no
   `music-server` process is left.

**If a track doesn't play**, run the app from a terminal to see the server
log and send the lines that start with `Using yt-dlp`, `Using ffmpeg` and
`YouTube …:`.

```bash
"/Applications/Music Manager.app/Contents/MacOS/music-manager"
```
